llm-proxy build board — proxy for LLM inference

Now — v0.0.1 "first light": one request, all the way through, for real. A client calls the proxy; the proxy routes it, opens TLS to the upstream gateway, forwards with credentials attached, and returns the response intact — streaming included. This release carries everything built to date. The features are not the milestone; the working path through them is. SHIP GATE — a chat-completion request, from a single llmproxy config pointed at a real provider, returns the provider's response unmodified — non-streaming and streamed SSE — for OpenAI and Anthropic. Verified by the #[ignore]d live smoke test in testing/diffrig, keys from env. One command. Currently red. The honest read: a great deal of machinery is green without ever having carried a real request — closing that is what this gate is for. Second standing gap: "performant" is an untested claim (no capacity sweep published; the v0.2.0 gate). WP-41, the black-box QA suite, found four real bugs on day one — no dialect access logs at all, %REQ(:METHOD)% always - (Envoy mode too), and no response flag on a mid-stream failure. Three fixed; the fourth (WP-33) is wired but has one unmet acceptance criterion. One had been described as intended in its own doc comment — the class of defect an inside view cannot see. Competitive review (Vercel AI Gateway) confirmed the plan and added WP-42/43/44: spend controls (a token/min cap is a throttle, not a budget), caching, cost-aware routing. They are managed-only, so self-hosting, Envoy config and xDS stay ours. WP-45 (new, 2026-08-01): a real upstream showed OpenAI-dialect streaming emits no usage block without stream_options.include_usage — the request-body rewrite pipeline that forces it also absorbs WP-35's body-peek model routing. v0.0.1 gate is unchanged: still red.
